> ステータス：構成案（記事の本文は未着手）
> 参考：Clipnote の `docs/design-user-guide.md` ・ `docs/user-guide/`

## 12.0 背景・目的

いまのヘルプは `/help`（`src/app/(main)/help/page.tsx`）の1ページに、見出しと短い説明を
並べただけの構成になっている。次の点が伝わりにくい。

- **金額の向きは2択なのに、名目は4通りある**こと（貸した／返済した／借りた／返済された）と、
  それが緑・赤の色や残高の符号にどう結びつくか
- **口座**が何のためにあるのか、多くの人は1つのままでよいこと
- **利子**の仕組み（年利 ÷ 52 の週利・未払利息を元本と分ける・返済はまず利息から）
- **共有リンク**で相手に何が見えるか（相手視点で符号と色が逆になる・期限90日・共有メモ）
- **相手のアーカイブ**で変わること・変わらないこと（利息だけは止まる）
- 統計の「返済の傾向」がどう計算されているか

これらを機能ごとの記事に分け、**各画面から該当する記事へ1タップで行ける**ようにする。

### 現行ヘルプの記述で実装とずれているもの

ガイドを書く前に、原稿の土台として把握しておく（ガイド化の際に正しい内容に置き換える）。

| 現行ヘルプの記述 | 実装 |
| --- | --- |
| 「精算」：相手ページから精算すると残高をゼロにする取引が自動で作られる | 精算ボタンは無い。残高が0のとき「精算済み」と表示されるだけ。精算は返済の取引を記録して行う |
| 取引のアーカイブ：「フィルタで非表示にもできます」 | すべての取引の絞り込み（`transaction-filter-sheet.tsx`）にアーカイブの表示切り替えは無い |
| アカウント設定：「テーマ（ダーク/ライト）を変更できます」 | 設定には「取引ボタンの表示」もあるが触れていない |

あわせて、パスワードの文字数の下限が **新規登録では8文字**（`actions/auth.ts`）・
**設定のパスワード変更では6文字**（`account-section.tsx` のクライアント側チェック）と食い違っている。
ガイドの「制限値」に書く前にどちらかへそろえる。

## 12.1 記事構成（案）

`docs/user-guide/{NN}-{slug}.md` に1記事1ファイルで置く（Clipnote と同じ命名。`NN` が並び順、
`slug` が画面から参照する識別子）。front matter は `title` だけ。

| # | slug | タイトル | 主な内容 | 主な導線元 |
| --- | --- | --- | --- | --- |
| 01 | `getting-started` | ツケカンをはじめる | ツケカンとは（自分ひとりで記録する・相手のアカウント不要）／3ステップ（相手を追加 → 取引を記録 → 残高を見る）／登録直後のオンボーディング（表示名 → 取引ボタン → 最初の相手 → 最初の取引。後ろ2つは「あとで」可）／画面の見取り図（ボトムバー4タブ・右下の＋）／ホーム画面に追加 | メニュー・ヘルプ入口 |
| 02 | `balance` | 残高と色の見かた | 金額の向きは2択（+ = 貸した・返済した／- = 借りた・返済された）／緑 = 受け取る側・赤 = 返す側／「精算済み」／ホームの合計（貸している・借りている）／相手ページの残高カード（口座ごとの内訳・元本／未払利息） | ホーム |
| 03 | `transactions` | 取引を記録する | ＋ボタンから記録（相手ページでは相手・口座が選ばれた状態で開く）／相手の並び順（最近記録した順）／名目ボタン／金額・用途（過去の用途のサジェスト）・メモ・日時・口座／取引の詳細から編集・アーカイブ・削除（アーカイブと削除の違い）／精算のしかた（返済の取引を記録する） | 取引フォーム（＋） |
| 04 | `transaction-list` | すべての取引を探す | 一覧の見かた（アーカイブ済みはグレー）／用途・メモで検索／相手で絞り込み／並び替え（日時・金額）／アーカイブ済みの相手の取引も出ること | すべての取引 |
| 05 | `partners` | 相手を追加・管理する | 相手の追加（アプリ未登録の人でよい・名前は重複不可）／相手ページの見かた／名前の変更／アーカイブで変わること・変わらないこと（一覧と候補から消えるだけ・残高や統計には残る・**利息は止まる**）／アーカイブ済みの相手の一覧と解除／削除 | 相手ページ・相手の設定 |
| 06 | `ledgers` | 口座を使い分ける | 口座とは（貸し借りのまとまり）／多くの人は1口座のままでよい・分けるとよい例（利子つき・用途別）／口座の追加・口座名／相手ページで口座ごとに絞り込む／口座の削除の条件（取引がある口座・最後の1つは削除できない） | 相手ページ（口座カード） |
| 07 | `interest` | 利子をつける | 年利で指定・週の利息 = 年利 ÷ 52（例：年利260% → 週5%）／選んだ曜日の0時（日本時間）に週1回／対象は残高がプラスの口座だけ・アーカイブ中の相手は対象外／未払利息として元本と分けてたまる／返済はまず利息に充てられる／単利と複利／次回の発生日と見込み額／過去の取引を直すと内訳も計算し直される | 口座の設定 |
| 08 | `share` | 相手と残高を共有する | 共有リンクの発行（相手はログイン不要）／相手に見えるもの・見えないもの（相手から見た向きで表示＝符号と色が逆・メールアドレスは出ない）／共有メモ（100文字・リンクがあるときだけ）／プレビュー／有効期限90日・再発行と無効化／URLを知っている人は誰でも見られる | 相手ページ（共有カード） |
| 09 | `statistics` | 統計で流れを見る | 全体の統計と相手ごとの統計の違い／期間（直近12ヶ月・今年・全期間）／名目5分類と、残高が0をまたぐ取引の分け方／返済の傾向の計算（古いものから埋まるとみなす・平均日数・1ヶ月以内の割合・未返済額）／動きのない貸し借り／集計対象（アーカイブ済みの取引は含まない・アーカイブ済みの相手は含む） | 統計・相手ごとの統計 |
| 10 | `settings` | 設定とアカウント | 表示名・パスワードの変更／取引ボタンの表示（「貸し借り両方」「よく貸す」「よく借りる」の3つと、それぞれのボタンの言い方を表で）／外観（ダーク・ライト）／ログアウト | 設定 |
| 11 | `faq` | 制限値とよくある質問 | 制限値の一覧／よくある質問 | 各記事の末尾 |

### 構成の考え方

- **Clipnote の「1画面 ≒ 1記事」を基本にする**。画面から「使い方」で飛んだ先がその画面の話だけになるようにする
- **02 `balance` を独立させる**。ツケカンで最初につまずくのは「どちらのボタンを押すか」「緑と赤のどちらが自分に得か」で、
  取引の記録（03）・共有（08）・統計（09）のすべてがこの考え方の上に乗っている。各記事から参照される土台の記事として早い番号に置く
- **口座（06）と利子（07）を分ける**。口座は全員に関係するが、利子は使う人が限られる。
  利子の説明を口座の記事に混ぜると、利子を使わない人が「口座は難しいもの」と受け取ってしまう
- **精算は独立した記事にしない**。精算専用の機能は無く、返済の取引を記録するだけなので、03 の1節にする

### 11 `faq` に入れる項目（案）

制限値（実装の値）

| 項目 | 値 |
| --- | --- |
| 相手の名前 | 50文字（同じ名前の相手は作れない） |
| 表示名 | 50文字 |
| 口座名 | 30文字 |
| 取引の金額 | 1回 1,000万円まで（円・整数） |
| 用途 | 100文字 |
| メモ | 1000文字 |
| 共有メモ | 100文字 |
| 年利 | 0〜5,200% |
| 共有リンクの有効期限 | 90日 |
| ログインの保持 | 90日 |

よくある質問

- 相手に通知されますか／相手もツケカンを使っていたら記録は連動しますか（どちらもしない。記録は自分だけのもの。見せたいときは共有リンク）
- 相手はアカウントを作る必要がありますか（不要）
- 精算するにはどうすればよいですか（返済の取引を記録する。0になると「精算済み」）
- 間違えて記録した取引は（編集・アーカイブ・削除。どれを選ぶか）
- 外貨や小数の金額は使えますか（円・整数のみ）
- 共有リンクを渡した相手に見られたくなくなった（無効化する。再発行すると古いリンクは使えなくなる）
- 利息が付かない（残高がマイナス・年利0%・相手がアーカイブ中・まだ発生曜日が来ていない）
- パスワードを忘れた／退会したい（いまはアプリ内の機能が無い。案内先を決める → 12.4）

## 12.2 原稿の書き方の決めごと（案）

Clipnote の決めごとをそのまま引き継ぐ。

- 形式は Markdown。読者はエンジニアではない前提で、内部名（Partner・Ledger・Transaction・`amount`・`kind` など）は本文に出さない
- 画面上の表示名と一致させる：「相手」「口座」「取引」「すべての取引」「統計」「メニュー」「共有リンク」「共有メモ」「未払利息」「元本」「アーカイブ」
- 記事間のリンクは `{{guide:slug}}` と書き、配信時に解決する（配信方式は 12.3）
- 例は具体的な金額で書く（「3,000円貸している相手から5,000円受け取ったら」のように）
- 各記事の末尾に「もっと知る」として関連記事を2〜4本並べる

## 12.3 配信方式（要決定）

原稿の置き場所（`docs/user-guide/*.md` を唯一の原本にする）は共通。どこで読ませるかで2案ある。

| 観点 | A. Clipnote の公開クリップ＋公開コレクションで配信 | B. アプリ内の `/help/[slug]` で配信 |
| --- | --- | --- |
| 実装 | Clipnote の `scripts/publish-user-guide.mjs` をほぼ流用できる。ツケカン側は manifest（slug → URL）とリンクだけ | Markdown を描画する仕組みを足す（ビルド時に取り込む）。ルートと記事一覧を作る |
| 本文の更新 | 公開スクリプトを実行するだけ。デプロイ不要 | 本文の修正にもデプロイが要る |
| 読み心地 | 別ドメイン（clipnote.paritto.dev）へ飛ぶ。ツケカンの見た目・ダークモード・ボトムバーとは切れる | ツケカンの中で完結。見た目・テーマがそろい、PWA として追加した人も外に出ない |
| URL | UUID の URL | `/help/interest` のような読める URL |
| 依存 | ツケカンのヘルプが Clipnote の稼働と運営アカウントに依存する | 依存なし |

**推奨は B（アプリ内）**。ツケカンはスマホで PWA として使われる前提のアプリで、ヘルプを開くたびに
別サービスのページへ出てしまうのは体験を損ねる。Clipnote が自分自身で配信したのは
「製品の価値を運営が実証できる（ドッグフーディング）」理由が大きく、ツケカンには当てはまらない。
本文の更新にデプロイが要るのは、`main` への push で自動デプロイされるので実害は小さい。

B の場合の画面構成：

- `/help`：ガイドの目次（いまの1ページのヘルプを置き換える）。記事を番号順にカードで並べる
- `/help/[slug]`：記事本文。`MobileHeader` の戻るは `/help`
- 未ログインでも読めるようにするか（ログイン画面・新規登録画面から「使い方」へ行けるようにする）は 12.4 で決める

## 12.4 画面からの導線（案）

Clipnote と同じく、各画面の見出しまわりから該当記事へ1タップで行けるようにする。

| 画面 | 記事 |
| --- | --- |
| メニュー・設定の「ヘルプ」 | 目次（`/help`） |
| ホーム | `balance` |
| すべての取引 | `transaction-list` |
| 取引フォーム（＋） | 置かない（下記） |
| 相手ページ | `partners` |
| 相手ページの共有カード | `share` |
| 相手の設定 | `partners` |
| 口座の設定 | `interest` |
| 統計・相手ごとの統計 | `statistics` |
| 設定 | `settings` |
| オンボーディングの「取引ボタンの表示」 | `balance` |

置かない導線（Clipnote の方針と同じ）

- 取引フォームなどのダイアログの中：1つの操作を終わらせるための画面で、外へ出るリンクは入力を途中で止めさせる
- 1画面から2記事へのリンク：相手ページは `partners` / `ledgers` / `share` に関係するが、見出しの「使い方」は `partners` の1本にし、
  口座・共有へは記事の本文から送る（共有カードだけはカード内に別のリンクを置く）

## 12.5 決めること

1. 配信方式：A（Clipnote）か B（アプリ内 `/help/[slug]`）か（推奨 B）
2. ログイン前（ログイン画面・新規登録画面）からガイドを読めるようにするか
3. 「パスワードを忘れた」「退会したい」への案内先（問い合わせ窓口を用意するか）
4. パスワードの文字数の下限を8文字と6文字のどちらにそろえるか（12.0）
5. 現行ヘルプの誤り（精算・アーカイブのフィルタ）を、ガイドの完成を待たずに先に直すか
