# 13. LP構成 下書き v1

ツケカンのLP（ランディングページ）の、訴求内容・セクション構成・コピー案・ビジュアル素材案をまとめた下書き。
実装（コンポーネント分割・デザイン）は、この下書きを固めてから別途行う。

材料にしたもの：

- `docs/`（要件・画面設計）と `docs/user-guide/`（使い方ガイド6本）、`CHANGELOG.md`
- 実装（`src/lib/transaction-labels.ts`・`src/lib/transaction-wording.ts`・`src/lib/balance-wording.ts`・取引フォーム・公開ページ・口座の設定・統計）
- 開発者が挙げたツケカンの良いところ（取引ボタンの表示・共有リンク・記録フォーム・ホーム・利子・相手ごとの統計・約1年の自分での運用）
- 参考LP：Clipnote（`~/projects/apps/clipnote` の `docs/lp-draft.md`・`docs/lp-visual-assets.md`・`apps/web/src/components/marketing/`）

## 0. 前提の整理

### 0-1. ツケカンをひとことで

友だちや家族との1対1のお金の貸し借り（ツケ）を、**自分ひとりで**記録しておくスマホ向けのWebアプリ。無料。

### 0-2. ターゲット

| 区分 | どんな人か | いまの管理方法 |
| --- | --- | --- |
| メイン | 友だちとの立て替え・貸し借りが日常的にある人。麻雀・飲み会・ランチ・旅行の立て替え・チケット代など、少額の貸し借りが何人もと並行して続いている（開発者自身がこの人） | 記憶、LINEの履歴、メモアプリ、スプレッドシート |
| サブ | 家族や親しい人と、まとまったお金を貸し借りしている人。返済が何ヶ月も続く、利子の取り決めがある | メモ、口約束 |
| 流入経路 | 共有リンクを受け取った人。公開ページの「ツケカンについて詳しく見る」から来る。相手視点の見やすさを**すでに体験している** | — |

### 0-3. ターゲットが抱えている課題

1. **「いくら貸してたっけ」**：何人もと並行すると覚えていられない。LINEをさかのぼるのもつらい
2. **記録がややこしい**：「返済された」はプラス？マイナス？ スプレッドシートだと符号を間違える。簿記の「貸方・借方」は難しい
3. **相手と数字がずれる**：「そんなに借りてたっけ」で気まずくなる。催促も言い出しにくい
4. **スマホで入れにくい**：スプレッドシートは外出先で入力しづらい（`docs/01-overview.md` の背景そのもの）
5. **既存のアプリが合わない**：割り勘アプリはイベント単位・グループでの精算が中心で、1対1で続いていく「ツケ」の残高管理には向かない。家計簿は自分の収支のためのもの

### 0-4. 訴求ポイント（優先度順）

| # | 訴求ポイント | 中身 | 対応する課題 |
| --- | --- | --- | --- |
| ① | 記録がかんたんで、正しく入る | 相手→金額→用途の順に入れるだけ。ボタンは「渡した」「受け取った」の向きの2つだけで、言い方は使い方に合わせて3種類から選べる。記録後は「貸した」「返済された」「借りた」「返済した」を残高から自動で言い分ける | 2・4 |
| ② | いまの貸し借りが、ひとめでわかる | ホームに差し引きの総額、「貸している」「借りている」の合計、相手ごとの残高。色は「緑＝受け取る／赤＝返す」でどの画面も同じ | 1 |
| ③ | リンクを送るだけで、相手と同じ数字を見られる | 相手はアカウントもログインも不要。公開ページは言葉も色も相手の立場に入れ替わる | 3 |
| ④ | 返済の傾向がわかる | 相手ごとに、平均何日で返ってくるか・1ヶ月以内に返ってきた割合・月ごとの推移。次に貸すか、利子をつけるかの判断材料に | 3 |
| ⑤ | 利子の取り決めも、ルールどおり自動で | 曜日・年利・単利/複利を口座ごとに。利息は元本と分けてたまり、返済はまず利息から。ルールは公開ページにも出る | 3 |
| ⑥ | 作り手が当事者 | 貸し借りの多い開発者が、約1年、自分の貸し借りを記録しながら直し続けてきた | （信頼） |

### 0-5. LPで誤解なく伝えたい前提（ツケカンの考え方）

「相手を巻き込まないと使えないのでは」という不安を先回りして消す。割り勘アプリとの一番の違いでもある。

- **記録するのは、あなただけ**：相手がツケカンを使っている必要はない。名前を登録すればその日から始められる
- **相手に通知はいかない**：記録したことが相手に伝わることはない
- **見せたいときだけ、リンクで見せる**：共有リンクを送ったときだけ、相手は記録を見られる

### 0-6. Clipnote のLPから取り入れる型

| Clipnote でやっていること | ツケカンでの置きかえ |
| --- | --- |
| HEROで「会話 → 保存 → 一覧」の流れを縦に見せ、使い方のイメージを最初に湧かせる | 「記録 → 取引 → ホームの残高」の流れを縦に見せる |
| 2章で、クリップ一覧の画面そのものを主役にする（「これは使いたくなる」） | 2章で、ホーム画面（総額と相手ごとの残高）を主役にする |
| ビジュアル素材は実スクショではなく、実コンポーネントを流用したモックアップ。ダミーデータを作り込む | 同じ。スマホ中心のアプリなので、ブラウザ枠ではなく**スマホ枠**で見せる |
| 機能セクションは1項目1〜2行の「一応紹介」 | 口座・検索・アーカイブなどを同じ扱いで |
| 終盤に、独自性を1セクション使って触れるデモで見せる（HTMLのライブデモ） | **「ことばの設計」を触れるデモで見せる**（ボタンの言い方の切り替え・名目の自動の言い分け・相手視点への反転） |
| CTAはHEROと最終CTAの2か所に絞る | 同じ |

`output/screenshots/` のスクリーンショットは旧UI（ホームのダッシュボード化・相手ページの見直し前）なので、そのままは使えない。

## 1. HERO：記録したら、残高まで出る

- **軸**：「友だちとの貸し借りを記録するアプリ」であることを一瞬で伝え、入れたらすぐ残高になる手軽さをビジュアルで見せる
- **見出し案**：
  - 候補A：友だちとの貸し借り、／ひとめでわかる。（推し。何のアプリかと、いちばんの効用が一度に伝わる）
  - 候補B：「いくら貸してたっけ」を、／なくす。（課題から入る）
  - 候補C：ツケは、／ツケカンに。（名前は覚えてもらえるが、何をするアプリかは伝わりにくい。OGP やフッターのタグラインに回す手もある）
- **サブコピー案**：相手と金額を入れるだけ。残高は自動で出る。
- **本文**：友だちや家族との立て替え・貸し借りは、何人もと続くうちに「誰に、いくら」がわからなくなりがち。ツケカンは、相手を選んで金額を入れるだけで、相手ごとの残高と全体の差し引きを自動で出す、貸し借り専用の記録アプリです。記録するのはあなただけ。相手にアプリを入れてもらう必要はありません。
- **CTA**：無料ではじめる（`/register`）のみ。ログイン中なら「アプリを開く」（`/`）
- **ビジュアル素材**：Clipnote の HERO と同じ、3つのカードを矢印で縦につなぐモックアップ
  1. 「新しい取引」の要約：相手「健太」／金額「¥3,000」／ボタン「貸した・返済した」が選ばれた状態／用途「麻雀」
  2. 記録された取引カード：「貸した・麻雀・¥3,000」、区切り線の下に「残高 ¥6,500」（緑）
  3. ホームの残高：「差し引きで受け取ります ¥19,550」、その下に相手カード3件（先頭が健太 ¥6,500）
  - 1で記録した健太の残高が、3の一覧の先頭にそのまま出ていることで「記録がすぐ反映される」をつなげて見せる

## 2. 考え方：相手を巻き込まない（短い帯・任意）

- **狙い**：0-5 の3点を、アイコン付きの3カラム（スマホでは縦積み）で短く見せる。HERO本文で足りるなら省略してもよい
- **項目**：
  - 記録するのは、あなただけ ── 相手の登録や了承はいりません
  - 相手に通知はいきません ── こっそりつけておける、自分用の記録です
  - 見せたいときだけ、リンクで ── 送った相手だけが、ログインなしで見られます
- **ビジュアル素材**：なし（アイコンのみ）

---

## 3. ホーム：総額と相手ごとの現状

- **狙い**：Clipnote の「管理」セクションと同じ位置づけ。機能の説明より、ホーム画面のビジュアルそのものを主役にする。「これなら把握できる」と思わせる
- **見出し案**：
  - 候補A：誰に、いくら。／ホームでぜんぶわかる。
  - 候補B：貸している・借りている、ひとめで。
  - 候補C：開けば、いまの貸し借りがわかる。
- **本文**：ホームを開くと、すべての相手をまとめた差し引きの残高と、「貸している」「借りている」の合計、そして相手ごとの残高が並びます。緑はあなたが受け取る側、赤は返す側、グレーは精算済み。この色の決まりは、取引・残高・統計のどの画面でも同じです。
- **補足（1〜2行）**：最近の取引もホームでそのまま確かめられます。やり取りが一段落した相手は、アーカイブすれば一覧からすっきり片付きます。
- **ビジュアル素材（本セクションの主役）**：ホーム画面のモックアップ（スマホ枠）。`BalanceSummaryCard`・相手カード・最近の取引を実コンポーネントのまま、付録のダミーデータで組む
  - 相手は5人。緑・赤・グレーが混ざるようにし、利子をつけている健太には「うち利息」を出す
  - 最近の取引は2〜3件

## 4. 記録：相手を選び、金額を入れ、用途を書く

- **狙い**：フォームのわかりやすさ。「迷わず入れられる」「必須は少ない」を見せる
- **見出し案**：
  - 候補A：相手、金額、用途。／それだけ。
  - 候補B：3つ入れたら、記録おわり。
  - 候補C：思い出したときに、その場で。
- **本文**：右下の「＋」から、相手を選んで、金額を入れて、用途をひとこと。必ず入れるのは相手と金額だけです。相手は最近記録した順に並び、用途はこれまで使ったものがよく使う順に候補に出るので、「麻雀」「ランチ」はタップで入ります。日時はふつう「現在」のまま。あとから思い出した貸し借りは、日時を指定して記録できます。
- **ビジュアル素材**：「新しい取引」のモックアップに、①相手 ②金額とボタン ③用途 の番号注釈を付ける
  - ①相手のボタン（健太・翔太・拓海…）で健太が選ばれている
  - ②「¥3,000」と、左右2つのボタン（左が緑で選択中）
  - ③用途の入力欄の下に開いた候補のリスト（返済／麻雀／飲み会／ランチ）
- **補足**：ボタンの言い方を選べることは、ここでは1行触れるだけにして、9章のライブデモで掘り下げる

## 5. 共有リンク：送るだけで、同じ数字を見られる

- **狙い**：独自性の柱。「リンクを送るだけ（相手はアカウント不要）」と「相手の立場の言葉で表示される」の2点を見せる。共有リンクから来た人には「あのページはこうやって作られている」が伝わる
- **見出し案**：
  - 候補A：リンクを送るだけで、／同じ数字を見られる。
  - 候補B：いくら借りてたか、／相手にもひとめで。
  - 候補C：「いくらだっけ」は、／リンクで解決。
- **本文**：相手のページで共有リンクを発行して、LINEやメールで送るだけ。相手はアカウントもログインもなしで、あなたとの残高と取引の記録を開けます。公開ページは相手が読むためのページなので、言葉も色も相手の立場に入れ替わります。あなたの「貸した」は、相手の画面では「借りた」に。「拓海さんから受け取ります」は「拓海さんはりくさんに返します」に。
- **訴求ポイント（文章で軽く。箇条書きにはしない）**：「月末までに半分返してくれると助かります」のような共有メモを添えられる。有効期限は90日で、いつでも無効にできる。ほかの相手の記録やメールアドレスは見えない。
- **ビジュアル素材**：2点構成
  1. **視点の反転（主役）**：左に「あなたの画面」、右に「拓海さんの画面（公開ページ）」を並べ、間を「リンクを送る」の矢印でつなぐ。同じ ¥3,200 の残高が、左は緑で「拓海さんから受け取ります」、右は赤で「拓海さんはりくさんに返します」。その下の取引「ライブのチケット代」も、左「貸した」⇔ 右「借りた」。利子のない拓海で見せると、内訳が出ずに反転だけが目に入る
  2. **送る流れ（補助）**：共有リンクのカード（「リンクをコピー」）→ チャットの吹き出しにURLが貼られている様子。チャット画面は LINE の見た目やロゴを使わず、汎用のトーク画面風にする

## 6. 統計：返ってくるまでの日数も、数字で

- **狙い**：記録がたまるほど価値が出ることを伝える。相手ごとの返済の傾向が主役
- **見出し案**：
  - 候補A：貸したお金、／平均何日で返ってくる？
  - 候補B：記録がたまると、／付き合い方が見えてくる。
  - 候補C：返ってくるまでの日数も、数字で。
- **本文**：相手ごとの統計では、貸したお金が平均何日で返ってきているか、1ヶ月以内に返ってきた割合、まだ返ってきていない額がわかります。月ごとの貸し借りや残高の推移もグラフで。次に貸すかどうか、利子をつけるかどうか──感覚ではなく、記録をもとに考えられます。
- **補足（1行）**：点数やランクはつけません。判断の材料になる数字だけを出します（`RepaymentCard` の方針と同じ。「信用を測る」を冷たく見せないための一文）。
- **ビジュアル素材**：相手ごとの統計（健太）のモックアップ
  - 返済の傾向カード：「貸したお金は、平均17日で返ってきています」「1ヶ月以内に返ってきた割合 86%」「まだ返ってきていない ¥6,500（古いものは9日前から）」「精算した回数 12回」
  - 月ごとの推移の棒グラフ（上が渡したお金、下が受け取ったお金）と、残高の推移
  - `RepaymentCard`・`movement-charts` を流用

## 7. 利子：取り決めた利子も、ルールどおり自動で

- **狙い**：個人間の貸し借りアプリで利子まで扱えるのは珍しい。ただし前面に出しすぎない（要相談 2）
- **見出し案**：
  - 候補A：利子の約束も、／ルールどおり自動で。
  - 候補B：取り決めた利子は、毎週自動で記録。
  - 候補C：利子のルールを、ふたりで同じように見られる。
- **本文**：口座に年利を設定すると、決めた曜日に週1回、利息が自動で記録されます。利息は元本と分けて「未払利息」としてたまり、返済はまず利息から充てられます。設定画面には「毎週水曜日に、元本に対して年利◯%の利息が発生します」とルールが文章で出て、次回の発生日と見込み額もその場で確かめられます。共有リンクのページにも同じルールが出るので、あとから「聞いてない」になりません。
- **ビジュアル素材**：
  - 口座の設定のルール説明（琥珀色のボックス）＋「次回 +¥50」のプレビュー（静的なLPに具体的な日付を書くと古くなるので、日付は表示時に計算するか曜日だけにする）
  - 残高カードの「元本 ｜ 未払利息」の内訳

## 8. 機能（一言紹介）

訴求の主力ではなく「一応紹介しておく」位置づけ。アイコン＋機能名＋サブコピー＋1行。ビジュアル素材はなし。4〜6件に絞る。

| 機能名 | サブコピー | 本文（1行） |
| --- | --- | --- |
| 口座 | 立て替えと、まとまった貸し借りを別々に。 | 1人の相手との貸し借りを口座に分けて、残高も利子も別々に管理できます。 |
| 検索・絞り込み | あの日の「ランチ」、すぐ見つかる。 | 用途・メモで検索、相手で絞り込み、金額順にも並べ替えられます。 |
| アーカイブ | 消さずに、片付ける。 | 取引も相手も、アーカイブならいつでも元に戻せます。 |
| 取引の詳細 | この取引で、残高がどう変わったか。 | 取引をタップすると、取引の前と後の残高を確かめられます。 |
| 動きのない貸し借り | 忘れかけたツケに、気づける。 | 残高が残ったまま60日以上取引がない相手が、統計に出ます。 |
| ホーム画面に追加 | アプリみたいに、すぐ開ける。 | iPhone・Android のホーム画面に追加できます。インストールはいりません。 |

## 9. ことばの設計：「貸方・借方」は出てきません（ライブデモ）

- **狙い**：Clipnote の「HTMLでできること」に相当する、終盤の独自性セクション。ツケカンいちばんのこだわり＝**お金の向きのややこしさを「ことば」で解決していること**を、触って体感させて最終CTAへつなぐ
- **見出し案**：
  - 候補A：「貸方・借方」は、／出てきません。
  - 候補B：プラスかマイナスか、／もう考えなくていい。
  - 候補C：「貸した」も「返済された」も、／ツケカンが言い分ける。
- **本文**：お金のやり取りの記録は、意外とややこしいもの。「返済された」はプラス？ マイナス？ ツケカンで押すボタンは、お金を「渡した」か「受け取った」かの2つだけ。ボタンの言い方は、貸すことが多い人・借りることが多い人・両方の人に合わせて3種類から選べます。記録したあとは、それまでの残高を見て「貸した」「返済された」「借りた」「返済した」をツケカンが自動で言い分けます。
- **ライブデモ（本セクションの主役）**：動画やGIFではなく、その場で触れるデモにする
  1. **ボタンの言い方を切り替える**：「貸し借り両方／よく貸す／よく借りる」のタブを押すと、2つのボタンのラベルと最初に選ばれている側が切り替わる。ボタンの並び（左が渡した・右が受け取った）は変わらないことも見せる
  2. **自動の言い分け**：金額を固定（例：3,000円・2,000円）したボタンを押していくと、取引が積み上がり、名目（貸した → 返済された → 借りた …）と残高・色が自動で変わる
  3. **相手から見ると**：トグルを入れると、同じ記録が相手の視点に反転する（共有リンクと同じロジック）
  - 実装メモ：実ロジック（`transaction-labels.ts` の `TRANSACTION_LABEL_OPTIONS`、`transaction-wording.ts` の `describeTransaction`、`balance-wording.ts`）をそのまま使える。Clipnote のような iframe は不要で、Client Component で作れる
- **配置意図**：機能紹介まで一通り伝えたあと、最後に「なぜ迷わず正しく入れられるのか」の答えを体感させ、最終CTAの後押しにする

## 要相談事項

実装（`src/app/page.tsx`・`src/components/features/lp/`）の前に、次のとおり決めた（2026-11-02）。

| # | 決めたこと |
| --- | --- |
| 1 | LPは `/` に置き、ログインの有無にかかわらず表示する（ログイン中はナビとCTAを「アプリを開く」にする）。ホームは `/home` に移す。公開ページの「ツケカンについて詳しく見る」は `/` に向ける |
| 2 | 年利13%（週0.25%）で見せる。年利の入力欄と「週3%」「週5%」のプリセットは載せない |
| 3 | 実コンポーネントを流用したモックアップにする |
| 4 | 付録のダミーデータのまま。オーナーの表示名は「りく」（仮） |
| 5 | 独立した帯にする |
| 6 | 下書きどおり三人称で、名前は出さない |
| 7 | まだないので、フッターには載せない |
| 8 | タイトル・説明文をLP向けに具体化し、OGP画像（`public/og-image.png`）を作る |

見出しは各セクションの候補Aを使う。

1. **LPの置き場所**：
   - 案A（推し）：未ログインで `/` を開いたらLP、ログイン中ならホーム。いまは未ログインの `/` は `/login` にリダイレクトしているので、そこをLPに差し替える。ただし `/` は `(main)` グループ（ボトムバー付きのレイアウト）にあるので、構成の見直しが要る
   - 案B：`/about` など別のパスに置く
   - どちらの場合も、公開ページの「ツケカンについて詳しく見る」のリンク先（いまは `paritto-dev-diary.vercel.app/products/tukekan`）をLPに向ける
2. **利子の見せ方と、例示する利率**：LPは誰でも見る宣伝ページなので、高い利率を勧めているように見えないよう配慮したい。参考までに、個人間の貸し借りでも、利息制限法の上限（元本10万円未満なら年20%）を超える部分は無効になり、出資法では年109.5%を超える利息の契約に刑事罰がある。アプリの年利プリセット「週3%」「週5%」は年156%・年260%なので後者を超える。LPの例示は年13%（週0.25%）に抑える案で下書きしている（7章の「+¥50」は元本20,000円・年利13%の値）。正確な扱いは専門家への確認を推奨
3. **ビジュアル素材の作り方**：Clipnote と同じく実コンポーネントを流用したモックアップ（推し）にするか、スクリーンショットを撮り直すか。モックアップなら大きく表示しても粗くならず、ダミーデータも自由に作れる
4. **ダミーデータ**：付録の名前・金額でよいか。オーナーの表示名「りく」は仮
5. **2章（考え方の帯）**：独立させるか、HERO本文に吸収するか
6. **10章（つくった人のこと）**：一人称で書くか、名前を出すか
7. **利用規約・プライバシーポリシー**：いまはない。お金の記録を預かるサービスとしてLPを公開するなら用意したい
8. **OGP画像・タイトル・説明文**：いまは「ツケカン - 友人間の貸し借り管理アプリ」「友人間の貸し借りを簡単に管理するアプリ」。LPに合わせて具体化する
