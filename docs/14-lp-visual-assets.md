## 1. 共通の方針

### 1-1. スクリーンショットではなく、実コンポーネントでモックアップを組む

Clipnote の LP と同じく、実画面のスクリーンショットではなく、アプリの実コンポーネントにダミーデータを渡して組む。

- 大きく表示しても文字がつぶれない。ダークモードにもそのまま追従する
- ダミーデータを自由に作り込める。アプリのデザインを変えたら、LPも自動で追従する
- `output/screenshots/` は旧UIなので使わない

実コンポーネントをそのまま使えるもの・作り直すものは次のとおり。

| 素材 | 使うもの | 備考 |
| --- | --- | --- |
| 全体の残高 | `BalanceSummaryCard` | そのまま |
| 相手カード | `PartnerCard` | `Link` なので、LPではクリックできないようにする（`pointer-events-none` か、リンクなし版を切り出す） |
| 取引カード | `TransactionCard` | そのまま。`viewpoint` を切り替えれば相手視点にもなる |
| 相手ページ・公開ページの残高カード | `BalanceCard` | そのまま。公開ページ側は `viewpoint="partner"` と `partnerBalanceStatement()` |
| 返済の傾向 | `RepaymentCard` | そのまま |
| 月ごとの推移・残高の推移 | `MonthlyMovementChart`・`BalanceHistoryChart` | そのまま（クライアントコンポーネント） |
| 取引ボタンの表示 | `TransactionLabelOptionButton`・`TRANSACTION_LABEL_OPTIONS` | そのまま |
| 取引フォーム | （作り直し） | 実物は react-hook-form と Server Action に依存するので、同じクラス名で見た目だけを再現する |
| 共有リンクのカード | （作り直し） | 実物は Server Action に依存するので、見た目だけを再現する |
| 口座の設定のルール説明 | （作り直し） | `describeInterestRule()`・`INTEREST_REPAYMENT_RULE_TEXT`・`getNextInterestPreview()` の文言と計算はそのまま使う |

数字や名目は手で書かず、実際のロジック（`describeTransaction`・`summarizeRepayment` など）にダミーの取引を通して出す。数字の食い違いを防ぐため。

### 1-2. 日付は「何日前」で持ち、表示するときに計算する

取引カードは「2分前」「昨日 21:00」「10/30」のように、表示した時点を基準に日付を出す。ダミーデータは「何日前」で持ち、表示するときに日時へ直す。

- LPをビルド時に静的に書き出すと、日付がビルドした時点で止まる。LPはリクエストごとに描画するか（Clipnote と同じ `force-dynamic`）、日付を含むモックはクライアントで組む
- 利息は「毎週水曜」なので、利息の取引だけは「直近の水曜からさかのぼって週ごと」に置く

### 1-3. スマホ枠

ツケカンはスマホ中心のアプリなので、Clipnote のブラウザ枠ではなくスマホ枠で見せる。

- 画面の中身は幅 390px で描き、枠ごと縮小して置く
- 枠は角丸の太いベゼルだけのシンプルなものにする。特定の機種（ノッチ・ダイナミックアイランド）は真似しない。ステータスバーも出さず、アプリのヘッダーから始める
- ホーム（4章）と公開ページ（6章）の枠は、Clipnote の公開ページのプレビューと同じく、**中を縦にスクロールできる**ようにする。はめ込みの静止画ではなく、本物の画面を見ている感じを出すため
- 下にボトムバー（ホーム／すべての取引／統計／メニュー）と右下の「＋」を出し、アプリの画面だと一目でわかるようにする

### 1-4. 見た目のトークン

- 色・角丸・フォントはアプリのトークン（`globals.css`）をそのまま使う。メインはエメラルド（`--primary`）、本文は Noto Sans JP
- ロゴはアイコン（`/icon-192.png`）＋ Zen Maru Gothic の「ツケカン」。「ツケ」をオレンジ（`#e07326`）、「カン」をエメラルドにする（ログイン画面と同じ）
- 強調にオレンジを使うのは、ロゴと最終CTAまわりだけにとどめる。緑・赤は「受け取る／返す」の意味を持っているので、飾りには使わない
- LP全体はシステムのテーマ（ライト／ダーク）に従う

## 3. HERO：記録 → 取引 → ホーム

Clipnote の HERO と同じく、3つのカードを下向きの矢印で縦につなぐ。カード全体を1枚の大きなカード（`rounded-3xl`・`bg-card`）に入れて、見出しの右（スマホでは下）に置く。

```
┌──────────────────────────────────┐
│ ＋ 新しい取引                       │
│ 相手   [健太]                       │
│ 金額   ¥3,000                       │
│        [貸した・返済した] [借りた・返済された] │
│ 用途   麻雀                         │
└──────────────────────────────────┘
                ↓
┌──────────────────────────────────┐
│ [貸した] 健太                 2分前 │
│ 麻雀                                │
│──────────────────────────────────│
│ 金額      ¥3,000 │ 残高     ¥6,500 │  ← 残高は緑
└──────────────────────────────────┘
                ↓
┌──────────────────────────────────┐
│ 差し引きで受け取ります               │
│ ¥19,550                            │
│ ● 貸している ¥32,050  ● 借りている ¥12,500 │
│ ┌──────────────────────────────┐ │
│ │ 健太                貸している  │ │  ← 枠を強調
│ │ 今日 · 麻雀          ¥6,500   │ │
│ └──────────────────────────────┘ │
│ ┌ 翔太 [2口座]        ¥22,350 ┐ │
│ └ 拓海                 ¥3,200 ┘ │
└──────────────────────────────────┘
```

- 1枚目は、フォームの要約。実物のフォームを縮めると細かすぎるので、相手・金額・ボタン・用途の4行だけにする。ボタンの見た目は実物と同じ（左が緑で選択中）
- 2枚目は `TransactionCard` そのもの（`partnerName="健太"`）
- 3枚目は `BalanceSummaryCard` と、`PartnerCard` を3件。健太のカードだけ枠を `ring-primary` で強調し、「記録したものがすぐここに出る」ことを示す
- 動き（任意）：表示時に1→2→3の順にふわっと出す。`prefers-reduced-motion` のときは出さない

アイコン＋見出し＋1行を3つ横に並べる（スマホでは縦積み）。アイコンは lucide。

| アイコン | 見出し | 1行 |

## 5. ホーム画面

本セクションの主役。スマホ枠に、`origin/main` のホームをそのまま再現する。中は縦にスクロールできる。

```
┌──────────────────────┐
│ ホーム              (?)│
│ ┌──────────────────┐ │
│ │差し引きで受け取ります │ │
│ │¥19,550            │ │
│ │●貸している ●借りている│ │
│ │ ¥32,050   ¥12,500 │ │
│ └──────────────────┘ │
│ 相手ごとの残高  相手を追加│
│ ┌ 健太      貸している ┐│
│ └ 今日·麻雀    ¥6,500 ┘│
│ ┌ 翔太[2口座]  貸している┐│
│ │ 昨日·タクシー代 ¥22,350││
│ └        うち利息 ¥350 ┘│
│ ┌ 拓海      ¥3,200  ┐│
│ ┌ ゆうき  借りている ¥8,000┐│  ← 赤
│ ┌ 美咲   借りている ¥4,500┐│  ← 赤
│ ┌ 花子    精算済み  ¥0 ┐│  ← グレー
│ 最近の取引     すべて見る │
│ ┌ [貸した] 健太  2分前 ┐│
│ ...               (＋)│
├──────────────────────┤
│ ホーム すべての取引 統計 メニュー│
└──────────────────────┘
```

- 最初に見えている範囲（スクロール前）に、全体の残高と相手カードの4〜5件目までが入るようにする。緑・赤・グレーがすべて目に入る
- スクロールすると「最近の取引」が3件続く（健太の麻雀 → 翔太のタクシー代 → 拓海のチケット代。水曜が近いと翔太の「利息」が入る。琥珀色の「利息」チップが見えるのはむしろ良い）
- 枠の外（デスクトップでは右、スマホでは下）に、色の決まりの凡例を小さく添える：「● 緑＝あなたが受け取る ● 赤＝あなたが返す ● グレー＝精算済み」

## 6. 記録フォーム

スマホ枠に、画面下から開いた「新しい取引」（実物はスマホではボトムシート）を出し、枠の外に番号つきの注釈を置く。

```
┌──────────────────────┐        
│      新しい取引       │        
│ 相手 *               │ ← ① 最近記録した相手から順に並びます
│ [健太][翔太][拓海]    │        
│ [ゆうき][美咲][花子]   │        
│ 金額 *               │ ← ② 押すのは「渡した」か「受け取った」かの2つだけ
│ ¥ 3,000              │        
│ [貸した・返済した][借りた・返済された]│
│ 用途                 │ ← ③ これまでの用途が、よく使う順に候補に出ます
│ ┌────────────────┐   │        
│ │ 返済            │   │        
│ │ 麻雀  ←ハイライト │   │        
│ │ 飲み会           │   │        
│ │ ランチ           │   │        
│ └────────────────┘   │        
│ 日時                 │ ← ふつうは「現在」のまま
│ [現在 (21:30)][日時を指定]│        
│ [        登録        ]│        
└──────────────────────┘        
```

- 相手は `PartnerPickerField` と同じ3列のグリッド（相手が5人以上なので3列）。健太が選ばれた状態（`bg-primary/10`）
- 健太は口座が1つなので、口座を選ぶ欄は出ない（実物と同じ）
- 用途の候補は、実物ではチップではなく入力欄の下に開くリスト。リストが開いて「麻雀」にカーソルが乗っている瞬間を描く。候補の順は全体のよく使う順（返済・麻雀・飲み会・ランチ）
- 注釈は、デスクトップでは枠の右に引き出し線つき、スマホでは枠の下に①②③の番号つきリストにする
- メモ欄は省く（必須でないことを見せたいので、入力欄を減らした見た目にする）。省いたことは本文の「必ず入れるのは相手と金額だけ」で補う

- 左は `BalanceCard`（`viewpoint="owner"`・`ownerBalanceStatement()`）、共有リンクのカード（見た目だけ再現。有効期限は表示した日から90日後を計算して出す）、取引カード
- 右は `BalanceCard`（`viewpoint="partner"`・`partnerBalanceStatement()`）、共有メモ、`TransactionCard`（`viewpoint="partner"`）。公開ページは中を縦にスクロールできる
- 間の矢印には、チャットの吹き出しに `tukekan.paritto.dev/share/…` が貼られた小さな絵を添える。LINE の見た目・ロゴは使わず、汎用のトーク画面風にする
- 同じ取引が左右でどう変わるかを、細い線や同じ高さに並べることで対応させる：「貸した ⇔ 借りた」「返済された ⇔ 返済した」「緑 ⇔ 赤」
- スマホ（LPの幅が狭いとき）は2台を並べられないので、「りくの画面｜拓海さんの画面」の切り替えタブにして、1台のスマホの中身を入れ替える

### 7-2. 補足のテキスト（図の下）

- 相手はアカウントもログインもいりません
- 有効期限は90日。いつでも無効にできます
- ほかの相手の記録や、あなたのメールアドレスは見えません

スマホ枠に「健太さんの統計」を出し、その横に `RepaymentCard` を拡大して重ねる（拡大表示の吹き出し）。数字は 2-2 の計算結果。

│ < 健太さんの統計     │      ┌────────────────────────┐

│ （0の上下をゆれる線）    │      │ ████████████████░░░    │
│ 返済の傾向          │      │ 返してもらった まだ返ってきていない 精算│
│ ┌健太さんの返済 ───┐│      │ ¥48,400   ¥6,500        12回│

## 10. ことばの設計：ライブデモ

Clipnote の「HTMLでできること」に相当する、触れるデモ。iframe は使わず、Client Component で作る。名目・残高・色はすべて実ロジック（`TRANSACTION_LABEL_OPTIONS`・`describeTransaction`・`describeBalanceRole`・`ownerBalanceStatement`・`partnerBalanceStatement`）で出す。

### 10-1. レイアウト

```
┌──────────────────────────────────────────────┐
│ 見ている人   [りくの画面] [健太さんの画面（共有リンク）]   │
├──────────────────────┬───────────────────────┤
│ ボタンの言い方            │ 健太さんから受け取ります        │
│ [貸し借り両方][よく貸す][よく借りる]│ ¥3,000（緑）               │
│                      │                         │
│ 金額 [¥1,000][¥3,000][¥5,000]│ ┌[返済された] 返済         ┐│ ← いちばん新しい
│                      │ │ 金額 -¥1,000 │ 残高 ¥3,000 ││
│ ┌──────────┐┌──────────┐│ └─────────────────────┘│
│ │貸した・返済した││借りた・返済された││ 貸しているときに受け取ったので │
│ └──────────┘└──────────┘│ 「返済された」             │
│ 押すと、そのまま記録されます    │ ┌[貸した] ランチ ¥3,000 │ ¥4,000┐│
│                      │ └[貸した] ランチ ¥1,000 │ ¥1,000┘│
│              [最初から]  │                         │
└──────────────────────┴───────────────────────┘
```

図は、初期状態から「¥3,000 で左」→「¥1,000 で右」と押したところ。

スマホでは「見ている人 → ボタンの言い方 → 金額 → 2つのボタン → 残高と取引」の順に縦に積む。

### 10-2. 動き

| 操作 | どうなるか |
| --- | --- |
| ボタンの言い方を切り替える | 2つのボタンのラベルと、塗りつぶされる側（最初に選ばれている側）が `TRANSACTION_LABEL_OPTIONS` のとおりに変わる。**ボタンの並び（左が渡した・右が受け取った）は変わらない**ことを、切り替えたときに小さく「並びはそのまま」と添えて見せる |
| 金額を選ぶ | 次に押したときの金額。初期値は ¥1,000 |
| 左のボタンを押す | +金額の取引を1件記録。名目は直前の残高から決まる（借りているときなら「返済した」、それ以外は「貸した」） |
| 右のボタンを押す | −金額の取引を1件記録。名目は直前の残高から決まる（貸しているときなら「返済された」、それ以外は「借りた」） |
| 見ている人を「健太さんの画面」にする | 残高の文と取引カードがすべて相手の視点に反転する（`viewpoint="partner"`）。ボタンの欄は薄くして「共有リンクのページは読み取り専用です」と出す |
| 最初から | 初期状態に戻す |

- 押すたびに一番新しいカードの下へ「なぜこの言い方か」を1行出す
  - 貸した：貸し借りがないとき（または貸しているとき）に渡したので「貸した」
  - 返済された：貸しているときに受け取ったので「返済された」
  - 借りた：貸していないときに受け取ったので「借りた」
  - 返済した：借りているときに渡したので「返済した」
- 相手視点のときは、この1行も相手の立場で出す
- 用途は名目から自動で入れる（貸した → ランチ、返済された／返済した → 返済、借りた → タクシー代）。「用途なし」の表示を避けるため
- 取引カードは新しい順に5件まで。残高が0をまたぐ取引（¥1,000 貸しているときに ¥3,000 受け取る）は、実物と同じく直前の残高で名目を決めるので「返済された」になり、残高が「借りている ¥2,000」（赤）になる。これもそのまま見せてよい
- 実物のフォームは「ボタンで向きを選んでから登録」だが、デモでは触ってすぐ結果が見えるように、ボタンを押したらそのまま記録する。ボタンの下の「押すと、そのまま記録されます」でそれを伝える

### 10-3. 初期状態

- 見ている人：りくの画面
- ボタンの言い方：貸し借り両方
- 取引：「貸した・ランチ・¥1,000」が1件だけある（残高 貸している ¥1,000）。空の状態から始めると、最初に何も起きていないように見えるため
- 相手は健太で固定（HEROから続く登場人物にする）

## 要相談事項（このドキュメントで増えたもの）

1. **利率の見せ方**：仮に年利13%（週0.25%・1週間 ¥50）で組んでいる。13章の要相談 2 で決めた値に合わせて、2-3・9章の数字を計算し直す
2. **オーナーの表示名「りく」**：仮。開発者の名前にするか、架空の名前にするか
3. **公開ページの見出し**：公開ページの見出しは今「拓海さんとの取引」で、読んでいる拓海さん本人に向けた見出しとしては少し不自然（「りくさんとの取引」のほうが読み手の視点に合う）。LPの7章で大きく見せるので、アプリ側の見出しも直すか決めたい
4. **ホームのスクロール**：スマホ枠の中をスクロールさせるのは5章（ホーム）と7章（公開ページの右側）だけにしているが、統計（8章）もスクロールさせるか
5. **ライブデモの簡略化**：ボタンを押したらそのまま記録する（実物は選んでから登録）という簡略化でよいか
6. **「単利／複利」の言い方**：口座の設定の選択肢は「単利」「複利」だが、使い方ガイド（`docs/user-guide/04-interest.md`）では「元本」「元本＋未払利息」と呼んでいて、そろっていない。LPの9章は「むずかしい言葉を使わない」という13章9の話と並ぶので、アプリ側をガイドの言い方にそろえるか決めたい
